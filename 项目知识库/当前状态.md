### INFRA-REL-001 已实现（`CATALOG_SYNC_NONRESUMABLE_UNDER_PLATFORM_RATE_LIMIT`）

- Commit `82a3031c254993a26f7bff55b02a5be90d1c141f`，`fix: resume catalog sync at dataset boundaries`，已 push（`3273a52..82a3031`，`0 0`）。
- 方案：dataset-boundary checkpoint，落在 `<cache_dir>/.alpha_catalog_sync_checkpoint/`
  = 一次性写入后 immutable 的 `manifest.json`（datasets 完整 records 内联，无 `datasets.json`、无 `completed_dataset_ids`、无 `updated_at`）
  + 每个已完成 dataset 一个 `fields/<sha256(dataset_id)>.json` envelope。
- **合法 envelope 是"该 dataset 已完成"的唯一权威**，因此"envelope 已落盘、manifest 未更新"的 crash window 不存在。
- 失败语义刻意不对称：manifest 层损坏 → `CatalogCheckpointInvalid`；context 变更 / datasets snapshot 变更（比完整 record hash，不只比 ID 集合）/ 超过 12h → `CatalogCheckpointStale`；两者都**不在同一 invocation 内自动从零重跑**。单个 envelope 损坏**只降级为重抓该 dataset**，绝不升级为 INVALID。
- manifest 校验在任何请求之前完成，被拒绝的 checkpoint 消耗 0 配额。
- 限流仍完全由 `PlatformAccessController` 负责：429 / `CircuitOpen` / transport / 校验错误一律保留 checkpoint 并向上抛；synchronizer 内无 sleep、无 retry、不调 interval。
- `resume` 默认 `False`，生产三处调用（`factory/runtime.py:167`、`main.py:532`、`tools/ops/refresh_catalog_and_reset.py:115`）行为与 `3273a52` 完全一致，不会写 checkpoint；仅 `tmp_validation_driver.py` 显式 `resume=True`。
- `resume` 路径下正式 cache 的 `cached_at` 取 checkpoint `started_at`，避免跨多个限流窗口的快照在完成瞬间伪装成"刚抓完"；非 resume 路径保持 finalize 时刻。
- 三份正式 cache 的 schema / key / context / source 不变；datasets/data-fields 严格分页 + operators 独立不分页的边界未动。
- 测试：`tests/test_platform_catalog_checkpoint.py` 38 例（覆盖约定的 11 个场景）；全量 `pytest -q` = 901 passed, 1 skipped。

### INFRA-REL-002 `MIXED_GENERATION_CACHE_UNDETECTED`（RECORDED / DEFERRED_OUT_OF_SCOPE）
